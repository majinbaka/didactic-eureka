# Mysteries, clues and foreshadowing

## Mystery record

MYST ID; question; truth/status; player initial belief; truth/partial-truth knowers; false leads; clues; foreshadowing; planned revelation; actual revelation event/audience; scoped status; possible payoff; dependencies/provenance.

Progression: HIDDEN → INTRODUCED → CLUES_AVAILABLE → PLAYER_SUSPICION → PARTIAL_REVELATION → REVEALED → RESOLVED. Use equivalent established vocabulary. Evidence availability does not imply suspicion; revealing truth does not necessarily resolve consequences. Optional discovery advances only its branch. Writer knowledge never establishes REVEALED.

Planned revelations/payoffs may be PROPOSED despite CANON truth. Never infer a canonical answer from an intentionally unresolved question.

## Clue record

CLUE ID; description; mystery; location; available-from event/time; discovery condition; player discovery state/event; other knowers; interpretation; possible misinterpretation; used-in-revelation; branch; provenance.

Availability, acquisition and interpretation are separate transitions. False leads identify false claims and supporting belief evidence without replacing truth. Filter found clues by occurrence and guard, not existence of definitions.

## Foreshadow record

FORESHADOW ID; setup; related mystery/event; first appearance; reinforcement; expected payoff; actual payoff; scope; provenance. Status: PLANNED, PLANTED, REINFORCED, PAID_OFF, ABANDONED.

PLANTED requires appearance in the queried history; PAID_OFF requires an actual payoff event. Planned payoff remains a plan. Abandonment preserves approved reason and impact. Check sufficient setup on payoff paths including optional/skip routes.
