# Characters, relationships and arcs

Every important character keeps a stable CHAR ID through name changes. Apply common bible metadata to records and mixed-status fields.

## Character record

| Group | Fields |
| --- | --- |
| Identity | ID, name, aliases, role, status, age/apparent age, appearance |
| Foundation | Background, personality, core traits, strengths, weaknesses, beliefs, values |
| Motivation | Want, need, fear, internal conflict, external conflict, secret |
| Connections | Relationships, shared history, important previous events |
| State | Location, goal, emotional state, physical state, last known state, as-of event/time/branch |
| Perspective | Knowledge, suspicions, false beliefs, important memories, acquisition sources |
| Obligations | Promises, lies, debts, items possessed with transfer IDs |
| Expression | Speech style, register, habitual phrasing, taboos, prior conversations |
| Development | Arc ID/stage, supporting events, planned versus achieved milestones |
| Provenance | Canon status, field-level evidence, confidence, approval, source revision |

Distinguish tendencies from guaranteed behavior. Fear does not rewrite permanent personality. A dead/injured/missing character's availability needs event-backed explanation; appearance cannot silently restore them.

Knowledge links to acquisition records rather than duplicating global truth. Promises/lies retain addressee, content, event, scope, awareness and fulfillment/exposure status. Secret identity is not a public alias merely because writers know it.

## Arc record

ARC ID; character; initial state; fear; false belief; pressure; first challenge; failure; realization; critical decision; changed behavior; final state. Every achieved milestone references occurred events and branch. Planned milestones remain conditional plans.

Stages: ARC-0 INITIAL → ARC-1 PRESSURE → ARC-2 RESISTANCE → ARC-3 CRISIS → ARC-4 CHANGE → ARC-5 PAYOFF. These are stage labels, not record IDs. Respect established alternative arc designs; regressions and branch arcs require causes. Do not advance stages solely because a summary asserts growth.

## Relationships

Store A→B and B→A separately when feelings differ. Event-backed updates explain trust, respect, fear, affection, suspicion, debt and conflict in words; preserve established numeric scales.

Example: EVENT-043, B protects A under `saved_A=true`: A trusts B more and owes a debt. This does not establish B's affection or affect paths where A was not saved.
